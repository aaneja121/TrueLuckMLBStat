Methodology

Contact Luck compares the run value a batted ball was expected to produce with the run value it actually produced. This page is how that comparison is built, and what it will and will not support.

{# ── Definition ────────────────────────────────────────────────────── #}

Definition

A fair batted ball carries an expectation. Given how hard it was hit, at what angle, and in what direction, the frozen model gives it a chance of each outcome, and those chances carry a run value. What happened on the field carries a run value too. Contact Luck is the difference.

Contact Luck Runs
The number of runs by which a batter's observed eligible batted-ball outcomes were more or less favorable than the model expected.
Contact Luck Runs per 100
Contact Luck Runs normalized to 100 eligible batted balls. This is the official public metric and the one the leaderboard ranks.
Positive value
More favorable realized outcomes than expected.
Negative value
Less favorable realized outcomes than expected.
{# ── Inputs ────────────────────────────────────────────────────────── #}

Inputs

Only fair batted balls are scored. Strikeouts, walks and hit-by-pitch never appear anywhere in this metric. A batted ball also has to pass the project's eligibility rules and carry the contact measurements the model needs. What clears both bars is an eligible batted ball, and it is the denominator behind every "per 100" figure on the site.

The measurements come from MLB Statcast. The contact model reads seven of them:

  • Exit velocity, in miles per hour.
  • Launch angle, in degrees.
  • Spray angle, approximate. It is derived from Statcast's visualization coordinates, so it is a directional signal rather than a verified measurement.
  • Hit distance, as Statcast records it.
  • Batted-ball type: ground ball, line drive, fly ball or popup.
  • Batter stance, left or right.
  • Venue.

The contact model has no input for who was batting. Two identical batted balls in the same park, off the same side of the plate, get the same expectation whoever hit them. One later stage does use a batter value: Statcast's season sprint speed, where infield and baserunner modelling needs it.

{# ── Expected run value ────────────────────────────────────────────── #}

Expected run value

The contact model predicts five outcome classes for every batted ball: out, single, double, triple, home run. Each class carries a fixed run value from a run-value table that never changes between plays or seasons. Expected run value is the model's probability of each class weighted by that class's run value. A play page shows the full distribution, so the expectation can be read rather than taken on trust.

The full expectation is built in stages, and a player page reports each one separately with its own model status:

Contact
What the batted ball was worth from its own measurements, before defense or baserunning.
Defensive opportunity and execution
Whether a fielder had a realistic chance on the ball, and how the actual defensive result compared with what a typical fielder does with that chance.
Advancement
Baserunner movement beyond the batted-ball outcome itself.
Unexplained residual
What the three modelled components leave over. It carries no model status because it is not modelled.

Components that are not yet fully calibrated are labelled as such wherever their value appears, and the share of a player's score that comes through them is printed on their page.

{# ── Observed run value ────────────────────────────────────────────── #}

Observed run value

Observed run value is what the play actually produced, in the same run units and off the same fixed table. It counts the whole play, baserunner advancement included, so it can differ from what the recorded result alone would suggest. A single that moves a runner from first to third is not worth the same as a single that does not.

The recorded result is the box-score outcome. The observed run value is the accounting. A play page shows both.

{# ── Contact Luck ──────────────────────────────────────────────────── #}

Contact Luck

On one batted ball, the whole metric is one subtraction:

Observed run value
what the play produced
−minus Expected run value
what the contact was worth
=equals Contact Luck
the gap, in runs

A positive gap means the play produced more than the contact was worth. A negative gap means it produced less. The sign carries the whole reading, which is why every figure on this site prints it.

{# ── Aggregation ───────────────────────────────────────────────────── #}

Aggregation

Per-play gaps add up. Summed across a player's eligible batted balls they are that player's Contact Luck Runs for the season to date, in real runs.

Divided by the number of eligible batted balls and multiplied by 100, they become Contact Luck Runs per 100. That rate is what the leaderboard ranks, and it is what makes two hitters with different playing time comparable.

A leaderboard figure is a rate over a whole season, not the run value of any one play. A hitter at +7.62 did not gain 7.62 runs on a batted ball. They gained 7.62 runs per 100 eligible batted balls across the season so far.

One more count appears on player pages. Scored Games counts games with at least one outcome-resolved eligible batted ball. It is not the same as official MLB games played. A game in which every plate appearance ended in a strikeout, a walk, or an outcome this metric cannot resolve contributes no scored game, even though the player was in the lineup.

{# ── Uncertainty ───────────────────────────────────────────────────── #}

Uncertainty

Every score ships with a 95% interval on the same per-100 scale, and it is drawn next to the point estimate on every ranked row. At season-to-date sample sizes most players' Contact Luck is not distinguishable from zero, and the site would rather say so than hide it.

The interval comes from a bootstrap that resamples games rather than individual plays. Plays within one game share a park, an opponent, a defensive alignment and a set of conditions, so treating them as independent observations would make every interval too narrow.

Each interval is also labelled by where it sits: entirely above zero, overlapping zero, or entirely below zero. That label is a description of the interval and nothing more. An interval that crosses zero is drawn exactly like one that does not, and it is never faded, muted, dashed or marked as an error. This site makes no significance claim about any individual player, and an interval crossing zero is not a finding of "no effect".

{# ── Qualification ─────────────────────────────────────────────────── #}

Qualification

Qualification decides who carries an official rank. It is decided before anyone is ranked, from thresholds fixed in advance. Every scored player keeps a page, a score and an interval whatever their status; only qualified players appear in the two official rankings.

Five statuses are checked in this fixed order, and the first one that applies wins. The reason a player holds no rank is specific to their status, and the reasons are genuinely different. A provisionally qualified hitter can hold more eligible batted balls than the top-ranked one.

Qualification statuses, in the order they are checked.
Order Status What it means
1 Not reportable No eligible batted balls at all, so there is no rate to compute.
2 Small sample Below the volume bar. The official rankings require at least 200 eligible batted balls and 100 scored games.
3 Insufficient component coverage Enough plays, but too much of this player's batted-ball profile falls outside both the defense and advancement models.
4 Provisionally qualified Clears volume and coverage. Too much of the value comes through provisional or limited-evidence pathways, or too many plays needed a fallback for a missing input. Where the value came from is what holds these players off the rankings.
5 Qualified Clears every threshold. Eligible for the two official rankings.

The volume thresholds are round numbers chosen in advance, loosely following MLB's own qualification conventions and scaled down because eligible batted balls are a subset of plate appearances. They were not selected by looking for a cutoff that produced an appealing leaderboard.

The current snapshot's breakdown by status is on the Data & status page.

{# ── Interpretation ────────────────────────────────────────────────── #}

Interpretation

Contact Luck describes what already happened. A high score says a hitter's results ran ahead of their contact over the batted balls in this snapshot. It says nothing about what those results will do next.

Reasonable readings:

  • Whose realized outcomes ran ahead of or behind their contact this season.
  • How large that gap is in runs, and how uncertain it is.
  • What happened on one batted ball, and how far it landed from expectation.
  • Which component of the accounting a player's score came through.

Readings this metric does not support:

  • That a hitter is due for a correction. Contact Luck makes no forecast.
  • That a hitter is good or bad. Split-half reliability is low by design, which is what a description of luck should look like.
  • That one player's defense or baserunning is better than another's. Components are shown with values and status, and no component is ever ranked.
  • That a player is distinguishable from average. Intervals are reported, and most of them cross zero.

The two rankings are "Most favorable realized luck" and "Least favorable outcomes relative to expectation". Neither is a list of good or bad hitters.

{# ── Limitations ───────────────────────────────────────────────────── #}

Limitations

  • It is retrospective. Contact Luck is a retrospective description of realized outcomes, not a measure of stable batting talent and not a projection of future performance.
  • Spray angle is approximate. It is derived from Statcast visualization coordinates through a community approximation. Treat it as direction, not as a measured angle.
  • Near-wall contact is the weakest area. Batted balls near the outfield wall use a specialist model that remains provisional. Its share of a player's score is reported rather than absorbed silently.
  • Weather is not modelled. Weather and air density were tested against the frozen model and not adopted. The gain was real but very small, and the per-play effects did not hold up as physically plausible.
  • Coverage is partial by construction. Only eligible fair batted balls are scored. A play the metric cannot resolve is excluded rather than guessed.
  • The data is daily, not live. Snapshots cover completed slates only. The date the site is current through is in the header and on the Data & status page.
{# ── Version and provenance ────────────────────────────────────────── #}

Version and provenance

The model is frozen. It is fit on earlier seasons and is never refit on the season it scores, so a score cannot move because the model learned from the plays it is scoring.

Scoring runs offline into dated snapshots that are never overwritten. This site is a set of static files built from one of them, and every number on it was computed before the page was built. Nothing is scored, trained or fetched when you load a page.
